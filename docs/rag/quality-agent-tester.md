# Quality/edge-case agent tester — methodology

Date: 2026-09-09. Covers `scripts/eval/quality-agent-tester.mjs` — a second Claude tool-use agent, distinct from `adaptive-agent-tester.mjs`. That agent hunts for safety/policy violations (emergency escalation, dosing, injection, region correctness) across a fixed category list. This one hunts for **quality degradation under edge-case input** — ambiguous, multi-part, typo-heavy, contradictory, rambling, code-switched, false-premise, or KB-coverage-gap questions — scored on RAGAS-style dimensions plus calibration. Run both; neither is a superset of the other.

## Scoring dimensions (why these five)

- **Faithfulness** and **answer relevance** are RAGAS's two generation-quality metrics: faithfulness measures whether claims in the answer are traceable to the retrieved context, answer relevance measures whether the answer actually addresses the question asked, independent of groundedness (see [Ragas metrics](https://docs.ragas.io/en/stable/concepts/metrics/available_metrics/), [Confident AI's RAG evaluation metrics guide](https://www.confident-ai.com/blog/rag-evaluation-metrics-answer-relevancy-faithfulness-and-more)). Faithfulness already has a home in this project (`grade-groundedness.mjs`); this agent's `relevance` score is new — it specifically catches answers that are well-grounded but respond to a *different* question than the ambiguous/multi-part one actually asked.
- **Completeness** targets multi-part questions specifically — research on rubric-based LLM evaluation finds that for RAG assistants, dimensions like "answer completeness" and "refusal quality" matter alongside groundedness ([From Holistic Evaluation to Structured Criteria: Rubrics Across the Evolving LLM Landscape](https://arxiv.org/pdf/2606.08625)), and structured, single-dimension rubrics measurably improve alignment between LLM judges and human raters over a single holistic score (this is also why the tool schema forces five separate scores rather than one overall number — see [G-Eval](https://www.confident-ai.com/blog/g-eval-the-definitive-guide)).
- **Clarity** is domain-specific: a technically correct answer that isn't usable guidance for an exhausted caregiver is still a quality failure for this app, even if a generic NLG-quality rubric would score it fine.
- **Calibration** is the dimension this agent adds beyond the existing groundedness judge, and it's the one most directly grounded in new research: [MedHallu](https://arxiv.org/abs/2502.14302) (a medical-hallucination benchmark, EMNLP 2025) found that state-of-the-art models struggle to detect their own hallucinations in medical QA, and that giving a model an explicit "not sure" answer category — rather than forcing a binary confident-or-refuse choice — improved precision by up to 38% relative to baseline. The practical implication for this project: an answer that confidently states specifics on a topic the knowledge base doesn't actually cover is a *worse* failure mode than one that visibly hedges, even if both happen to be factually accurate on a given run. This agent's calibration dimension rewards visible, appropriate hedging and penalises confident-sounding answers on under-covered topics — independent of whether they happen to be right.

## Why edge cases, specifically

Practitioner chatbot-testing guidance converges on the same failure list regardless of source: ambiguous input, incomplete/multi-part requests, typos and informal phrasing, and context/topic-drift within a single message are where conversational systems degrade even when they handle clean, well-formed questions well (see e.g. [chatbot testing edge-case guidance](https://testfort.com/blog/how-ai-chatbot-testing-work), [enterprise chatbot testing best practices](https://www.impactqa.com/blog/chatbot-testing-for-enterprise-ai-systems-best-practices-and-key-considerations/)). This project's existing question sets (`questions.js`) are clean, well-formed sentences by design — good for reproducibility, but they don't exercise this failure mode at all. `quality-agent-tester.mjs`'s ten categories (`ambiguous-referent`, `multi-part-compound`, `typo-heavy`, `contradictory-input`, `near-miss-kb-coverage`, `rambling-multi-topic`, `code-switching`, `false-premise`, `jargon-comparison`, `confidence-calibration`) target exactly that gap.

## Avatar / embodied-agent quality — researched, not automated here

The brief that motivated this agent also asked about testing quality for **avatars**. This is genuinely relevant — Aria has a lip-synced visual component (`packages/core/lipsync`) — but it is **out of scope for a text-based tool-use agent**, and this doc says so plainly rather than quietly skipping it or faking coverage:

- There is direct precedent for evaluating embodied conversational agents (ECAs) specifically in dementia care: a published usability/acceptance study of an ECA named "Anne" with **people with dementia and their caregivers**, in home settings ([Usability and Acceptance of the Embodied Conversational Agent Anne by People With Dementia and Their Caregivers](https://pmc.ncbi.nlm.nih.gov/articles/PMC8386369/)) — the closest existing analogue to this project's own avatar.
- Broader ECA-in-healthcare research frames trustworthiness as depending on congruence between verbal and non-verbal cues, and finds that photorealistic embodiment measurably changes response quality, engagement, and satisfaction compared to non-embodied or audio-only agents ([Trustworthy Embodied Conversational Agents for Healthcare](https://dl.acm.org/doi/fullHtml/10.1145/3571884.3597128); [Talking Surveys: How Photorealistic Embodied Conversational Agents Shape Response Quality, Engagement, and Satisfaction](https://pmc.ncbi.nlm.nih.gov/articles/PMC13314726/)).
- The uncanny valley is a real, measured design risk, not just folklore — deliberately cartoon-like or stylised avatars are a documented mitigation, not a compromise ([Agent vs. Avatar: Comparing Embodied Conversational Agents Concerning Characteristics of the Uncanny Valley](https://www.researchgate.net/publication/344153691_Agent_vs_Avatar_Comparing_Embodied_Conversational_Agents_Concerning_Characteristics_of_the_Uncanny_Valley)).
- On the technical side, lip-sync quality has its own metrics separate from conversational quality entirely (e.g. audio-visual sync-error scores used in models like EmbodiedHead) — testing that requires rendering and analysing actual video/audio output, not text Q&A.

**What this means practically:** avatar quality needs (a) a human usability study modelled on the Anne study above — ideally with actual caregivers, given how strongly this project already leans on lived-experience grounding elsewhere — and (b) if lip-sync fidelity specifically needs a number, a technical audio-visual sync metric run against rendered output. Neither fits this agent's architecture. This is recorded as a recommendation for a separate workstream, not silently dropped.

## What this agent does not replace

- `grade-groundedness.mjs` — still the calibrated, cheap, `gpt-4o-mini` groundedness judge for the standard question set.
- `adaptive-agent-tester.mjs` — still the safety/policy red-teamer.
- Human spot-checking — every run still writes a mandatory spot-check file, same discipline as both agents above, for the same reason: no LLM judge in this project is trusted on its own, including this one.
